# WDMCH measurement — 2026-10-02

Read-only inventory of the real machine, taken over SSH after it answered ARP
again. Every command below reads. Nothing was written to the WDMCH at any
point, and no rescue image was ever booted on it.

This file exists because the project's storage plan was built on an assumption
that had never been checked, and the machine falsified it. The assumption is
recorded here so the next person does not repeat it.

## How it was taken

```bash
ssh dietpi@192.168.1.2 'bash -s' < tools/preflight.sh
```

## Headline

**p20 SYSTEM_B is the root filesystem of the running system.** Installing Alpine
into p20, which is what this project was designed to do, would have destroyed
the machine.

## The decisive facts

Taken directly, not inferred:

```text
$ blkid -o export /dev/sda20
LABEL="(none):1"  TYPE="linux_raid_member"  PARTLABEL="SYSTEM"
UUID="dddddddd-1111-1111-1111-1111aaaaaaaa"

$ cat /proc/mdstat
md1 : active raid1 sda20[0]
      20954112 blocks super 1.2 [2/1] [U_]

$ findmnt -n -o SOURCE,FSTYPE,LABEL /
/dev/md1 ext4 SYSTEM
```

`[2/1]` is a **degraded** two-device RAID1 with one member present. That member
is p20. The array it forms is the root filesystem.

## Why every candidate is refused

| Partition | Size | State | Verdict |
|---|---|---|---|
| p19 SYSTEM_A | 3 GiB | enabled as **swap**, 0 bytes used | refuse — it is the swap device of a running system |
| p20 SYSTEM_B | 20 GiB | **root filesystem** via md1 | refuse — would destroy the system |
| p21 DATA | 7.3 TiB | btrfs, 12 GiB used, 7.24 TiB free | refuse — the data disk, and not in the allowlist |

There is **no safe target partition on this machine.** `tests/test_wdmch_layout.sh`
runs the installer's real refusal against these recorded values and asserts all
three are refused.

## The system that lives here

Not a plain Debian box, and not a NAS:

- `/` is a **Nix/Guix** install — `/nix` and `/guix` both present, 5.9 G used
- 960 MiB RAM, **load average 3.5** on 4 cores
- swap is provided by `zram0` (243 M used); `sda19` is enabled but idle
- FidoNet is **confirmed and running**: `fidonet-bbs`, `fidonet-inotify`,
  `fidonet-telegram`, with `/etc/fido` and `/var/spool/fido`
- avahi, cups, cups-browsed, dovecot, fail2ban, distcc, earlyoom also running
- `/home`, `/var` and `/srv` are all on the btrfs DATA partition

## What this changes

The project was designed on one premise: *p20 SYSTEM_B is a spare vendor slot,
safe to overwrite, and nothing else is touched.* On a factory WDMCH that is
true. On this machine it is false, and the difference is the whole difference
between a maintenance task and destroying a working system.

`install-alpine` now refuses any target that already holds a filesystem other
than ext4, or that is named in `/proc/mdstat`. That guard did not exist before
this measurement, and none of the existing guards would have fired: the factory
GPT is intact, p20 is on the allowlist, and it is not the rescue stick.

## Recommendation

Do not migrate this machine. It has no free slot to migrate to, it runs a
service estate with no Alpine packaging, and it is already under memory
pressure. The project keeps its value as a **rescue and maintenance tool** -
see [ROADMAP.md](../../ROADMAP.md) §5 and [STRATEGY.md](../../STRATEGY.md).
